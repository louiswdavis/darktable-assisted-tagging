# Testing and development

Part of [darktable-assisted-tagging](../README.md). The Windows acceptance checklist, the tests and the helper tools.

## Acceptance checklist

The darktable side of grouping support, the neighbour aid and the `settings:` log line has not been run in darktable yet. Work through these steps on Windows, in order, and note the result of each. The log is `%LOCALAPPDATA%\darktable\assisted_tagging.log`; each run ends with `run finished`.

**Setup**

1. **Python tests.** In the repo folder: `.venv\Scripts\python python\run_tests.py`. *Expect:* every test passes, including `test_neighbour`, `test_import_numbers`, `test_import_start_list` and `test_identify`.
2. **Install the plugin** as in [Install](../README.md#2-darktable-side) and start darktable. *Expect:* an **Assisted Tagging** panel in lighttable showing *new collection* on the `template` preset; on a collection, **Open entries.json**, the page buttons *1 collection ▾* (open, its settings below it) to *6 references ▸*. No `LUA ERROR` in the darktable log.
3. **A collection.** Set the plugins folder preference, then make a collection (from tagged images, or from the `f1-season` example plus a few references). *Expect:* it appears in the **Preset** dropdown.

**Grouping support** (one run per mode, on a selection holding a burst)

4. **Native groups.** Put the burst in a darktable group, pick *Native groups*, click **Identify Selection**. *Expect:* in the log, `identify started`, then `settings: … grouping support native, node (blank), neighbour tolerance 5`, then `group support native: N of M images in groups of 2+` with N counting the burst.
5. **Grouping tags, blank node.** Run Assisted Grouping on the selection with **Group tags** on. Back in tagging, pick *Grouping tags*, leave the node blank, run. *Expect:* `group support tags: N of M images in groups of 2+, latest run per image (1 runs)`.
6. **Grouping tags, wrong node.** Type a node no selected image carries, run. *Expect:* `group support tags: 0 of M images in groups of 2+, node <what you typed> (matches no selected image)`; every image is its own group.
7. **None.** Pick *None*, run. *Expect:* `group support none: 0 of M images in groups of 2+`.

**Neighbour aid and references**

8. **Neighbour aid.** Make a collection from the `rally` example and run on cars shot roughly in number order. *Expect:* `neighbour: resolved N, flagged M (order weight …, tolerance 5)`; frames it settled get *By neighbour*, unsupported low-confidence reads get *Check order*. Set **Neighbour Tolerance** to 3 and re-run: both the `settings:` and `neighbour:` lines say 3. Then select only a few frames from the middle of an already-tagged run and Identify again. *Expect:* `neighbour: N unselected tagged images shot near the selection` with N above 0, the same count in `unselected tagged images lend support`, and no tags changed on the unselected images.
9. **Zero references.** Run on a collection with no references. *Expect:* `collection … has no references yet: only numbers can identify a car`; the run finishes, and cars with no readable number are *Unidentified*.

**Panel**

10. **Cancel.** Start **Identify Selection** on a large selection and click it again. *Expect:* "Assisted Tagging: cancelled, no tags were changed."
11. **No selection.** Clear the selection and click **Identify Selection**. *Expect:* "Assisted Tagging: select some images first".
12. **Diagnostic switches.** Identify a batch with every switch on. Under **Tags Written** in the panel, turn off *Shot* and *By livery*, choose **Actions** → **update preset**, then identify the same batch again. *Expect:* the same entry tags as before; no image in the batch has `…|Identification|Shot|…` or `…|By livery`; the other diagnostics are still there. No `LUA ERROR`.
13. **Start list import.** Save a 100-row CSV (`No.;Driver;Co-Driver;Entrant;Class`), choose it under **Start List** and click **Import Start List**. *Expect:* "Added 100 entries to entries.json"; the entries have `name` (the driver), `co_driver`, `team` and `extra` (the class); `entries.json.bak` is the previous file. Click **Import Start List** again. *Expect:* "Added 0 entries … skipped 100 already listed: 1, 2, …". Open the **Single Entry** tab (the button now reads **Add Entry**), type number `8`, driver `Smith`, team `Smith Racing`, colour `Red`, and click it. *Expect:* "Added 1 entry to entries.json", entry 8 has `name` Smith, `team` Smith Racing and `colour` Red, and the boxes are cleared. Import with the number box blank. *Expect:* "Type the entry's number first.", nothing written. In an `entries.json` copy, set one entry's `name` to `Smith / Jones` with no `co_driver`, select an image carrying its number tag and click **Find New Entries** on the Tools page. *Expect:* a `split "Smith / Jones" → driver Smith, co-driver Jones` row; ticking it and adding gives that entry `"name": "Smith", "co_driver": "Jones"`.

14. **Old settings.** Remove `tag_shot_crowded` and `tag_shot_crowded_name` from a collection's `settings.json` (keep `tag_shot` off), then click **Reload**. *Expect:* the log shows `settings.json: tag_shot_crowded, tag_shot_crowded_name copied from the Shot switch (old settings)`, and *Shot crowded* is off in **4 Tags Written**.
15. **Clear Tagging Marks.** Identify a burst, then add `Rally|2026|12` to one image by hand. Select the burst and click **Clear Tagging Marks**. *Expect:* "Assisted Tagging: cleared N tags from M images."; every tag the plugin attached is gone, the hand tag stays, and a later **Identify Selection** treats the images as fresh. Click it again on the same selection. *Expect:* "Assisted Tagging: nothing to clear; the selection has no tagging marks."
16. **Export and import a collection.** With a collection that has entries picked, choose **export preset…** in the actions menu, then **Export** (no folder to pick). *Expect:* `Preset "<name>" exported to <plugin folder>\exports\<name>.atpreset.zip`; the zip holds `manifest.json`, `preset.json` and `entries.json`, and no `refs` folder. Pick **import preset…**, choose that zip, click **Import**. *Expect:* `imported "<name> (2)" …`; a `<name> (2)` folder appears under the collections folder with `settings.json` and `entries.json`, and picking it in the collection list shows the same entries (references are empty until you add some). Export again with the **References** box ticked. *Expect:* the box reads `references (<n> files, <size> MB)`; `exported to …\<name>.atpreset.zip (replaced the earlier export)` (no `<name> (2).atpreset.zip` appears); the zip now also holds a `refs` folder (crops plus `sources.json`) and no `index.npz`. Export again with nothing changed. *Expect:* `already exported and unchanged`, and the zip keeps its time. Import that bundle. *Expect:* `<name> (3)` has the `refs` folder, and the first Run on it embeds the references before tagging (no audit needed).
17. **Copy Tags to Group.** Group a burst in darktable. Fix one image by hand (right entry, number and colour tags), and give another image in the burst a wrong number tag. Select only the fixed image and click **Copy Tags to Group**. *Expect:* "Copy Tags to Group done, N tag changes on M images."; every image in the burst has the fixed image's entry, number and colour tags, the wrong number tag is gone, diagnostics such as *Check colour* stay, and a burst image that was *Unidentified* loses that tag and its *Number seen* tags. Run **Identify Selection** on the burst with **Replace Manual Tags** off. *Expect:* the copied tags stay. Now select two images of one group that carry different number tags and click it again. *Expect:* a box under the button says the selected images in 1 groups have different tags, and nothing changes until **Merge and Copy**; **Cancel** hides it with nothing written.
18. **Possible new entries.** Remove one car's entry from an `entries.json` copy, then **Identify Selection** on a burst where its number is clear on 3+ images. *Expect:* the log has `new numbers: <n> (<k> images); read on 3+ images of a burst, no entry has them`, those images carry `Number seen|<n>` (an identified image too), and To Check has "Possible new entries: <n> (<k> images)…" with one line per image. Click **Find New Entries** on the Tools page. *Expect:* a row for <n>; adding it retags those images with its number tag.
19. **Lock In Tags.** Identify a burst, check one image is right, select it and click **Lock In Tags**. *Expect:* "Lock In Tags done, N tag changes on 1 images."; the image has `Assisted Tagging|Locked`. Tick **Replace Manual Tags** and run **Identify Selection** on the burst. *Expect:* the log has `<id>: locked, skipped`, the locked image keeps every tag, and unread frames of the burst take its entry. Run **Copy Tags to Group** from another image of the group. *Expect:* the locked image is unchanged. **Unlock Tags** removes the Locked tag only.
20. **Identify Missing Entries.** Tag most of a shoot, leave two entries untagged, select the shoot and click **Identify Missing Entries**. *Expect:* the log has `missing entries: <a>, <b>`; images it finds carry that entry plus `Check match`; the message says "Found <n> of 2 missing entries…". With every entry tagged, the button says "Every entry has an image." and runs nothing.
21. **Entry search and Apply Entry.** On the Tools page type part of a brand, model, driver name or number into the search box under Add to One Entry. *Expect:* matching entries list below it with the tags that matched, and **Match** shows them. Add a second word that excludes one. *Expect:* it drops out. Select an image, pick an entry in **Match**, click **Apply Entry to Selected**. *Expect:* "Applied <id> to 1 image." and the image carries that entry's tags. Run **Identify Selection** with **Replace Manual Tags** off. *Expect:* the tags stay.
22. **Copy Tags from Group.** Group a burst; fix one image by hand, leave another untagged. Select only the untagged image and click **Copy Tags from Group**. *Expect:* "Copy Tags from Group done…"; it now has the fixed image's entry, number and colour tags. Select an image whose group mates carry no entry tags. *Expect:* a message says so and nothing changes.

### Report what breaks

For each step that doesn't match, send back:

- the step number, and what happened instead (screenshot if it's visual)
- `assisted_tagging.log` from `%LOCALAPPDATA%\darktable` (copy it right after the failing step; the next run moves it to `assisted_tagging.prev.log`)
- any `LUA ERROR` lines from `Documents\Darktable\darktable-log.txt`, with darktable started with `-d lua`

## Development

### Tests

From the repo root. The Python tests use synthetic images and stub models, so they need no model files. `run_tests.py` runs every `python/test_*.py` and the Lua suites `lua/test_assisted_tagging.lua` (the darktable-independent functions) and `lua/test_assisted_gui.lua` (builds the panel and runs the button functions against a fake darktable and a fake identify.py process) (or only the ones named, e.g. `match neighbour assisted_tagging`), prints one summary line each and writes each one's output to `tests/<name>.txt`. The Lua suite uses a `lua` on PATH if there is one, else lupa: run `pip install lupa` in the venv once (Windows has no `lua` by default):

```
# Linux / macOS
.venv/bin/python python/run_tests.py

# Windows
.venv\Scripts\python python\run_tests.py
```

On a Mac or any machine without numpy and OpenCV, the standard-library tests still run (`python python/test_settings.py`, `python python/test_import_numbers.py`), as do the Lua suites; the rest need the venv.

The Lua suite alone: `.venv\Scripts\python python\run_tests.py assisted_tagging` (or `cd lua && lua test_assisted_tagging.lua` with Lua 5.4).

### Running the identifier on its own

`manifest.csv` is `id,filepath,burst_id` per line, with an optional fourth column, the `;`-joined entry tags the user applied by hand (an image carrying all of one entry's are skipped; a solo result sharing none of them is held back as `conflict`). Further optional columns: the fifth is the `;`-joined team tags used as hints, the sixth the capture time in seconds, the seventh the id of the entry the user's own number or driver tag names (results use the method `hand` for it):

```
python python/identify.py manifest.csv results.csv --collections-root collections --collection "F1 2026" \
    --detector models/object_detection_yolox_2022nov.onnx --ocr-det models/text_detection_en_ppocrv3_2023may.onnx \
    --ocr-rec models/en_PP-OCRv5_mobile_rec.onnx --embedder models/dinov2_small.onnx
```

`--ocr-rec` takes the CRNN model too. `--settings PATH` uses that settings file instead of the collection's `settings.json` (the panel passes a temporary one for its runs; `promote_boxes.py`, `audit_refs.py` and the list modes take it too). Set `order_weight` and `neighbour_tolerance` in that file.

`results.csv` gets `id,box,method,entry_id,alt_entry_id,confidence,unmatched_number,shot,order_flag,colour,colour_flag,sponsor,anchor_flag,new_number` per vehicle (`new_number`: the numbers no entry has that this box read across its burst, `;`-joined) (box −1 for a frame with no vehicle; method `skipped` or `conflict` as above). Exit codes: 0 ok, 2 bad input (the message is on stderr), 3 missing package, 130 cancelled.

`--boxes-out PATH` also writes `boxes.json`, one record per vehicle: `{"collection", "thresholds" ({min_sim, min_margin, ocr_min_score, number_min_height, min_read, weak_read_min, number_list_margin, number_list_floor, noise_min_partners, noise_min_beside_share, number_gate_min}: the values the run used), "noise_numbers" ({digits: how many start-list numbers it was read beside}), "entry_list" (the run's `entry list:` log lines), "new_numbers" ({digits: images}: 1 to 3 digit numbers no entry has, read on 3+ images of one burst), "sponsor_keywords" ({word: tag prefix}), "entries": {id: {"team", "number", "tags", "camera", "colour", "car", "refs"}}, "images": {id: {"shot", "status" (ok, no_vehicle or error), "file", "frame", "burst", "time" (capture epoch seconds, null if EXIF is missing), "note" (the detector's text when it found no vehicle), "boxes": [{"box", "bbox", "score" (detector confidence), "entry", "alt_entry", "method", "confidence", "candidates" (top 5 entry/similarity), "ocr", "ocr_trace" (the five most confident text regions, [confidence, text, height share of the crop]), "pod" ({yellow, aspect}: the camera-pod reading), "overlap" ("" , "trimmed" when read on the part not covered by a car in front, "hidden" when too little was left to match), "rescued" ({from, sim} when burst rescue found this box, else {}), "decided_by", "gap", "unmatched_number", "new_number", "conflict", "hint" (prefixes, source, restricted, dropped, reason; {} without one), "order_flag" (a doubtful number read no neighbour supports), "pod_colour", "hires" (read again from the larger decode), "masked" (cropped with a mask), "colour", "colour_shares", "list_read" (the start-list scoring of the read), "read_entry" (the entry the number read alone named), "number_share" (with `number_gate` on: how strongly SigLIP 2 saw a number on the crop, 0 to 1; null where the gate did not look)}], "hand" (the entry your own number or driver tag names), "tagged" (the entry whose tags the image already carries)}}, "skipped": [ids]}`. With `--verify` each box also has `ocr_regions`, `ocr_ctc` and `sims`, which `eval_numbers.py` replays. For `none` boxes `decided_by` names the rule that failed (`no_references`, `below_min_sim`, `margin_too_small`) and `gap` how far short it fell. The plugin writes it to `last-run/<collection>.boxes.json` in its config directory; `--promote-boxes --boxes-in PATH` (same manifest, `id,filepath,""`) saves its confident boxes as references.

### Debug report

Every run also writes `last-run/<collection>.report.md` and `.report.json` in the plugin's config directory (the path is logged as `report: …` in `assisted_tagging.log`). Each vehicle gets one category: `identified`, `team-obvious` (team clear, driver not separated), `weak-match`, `no-references`, `number-unmatched`, `conflict` (disagrees with a tag you applied), `overlapped` (a car mostly covered by another in a pack: not matched, its visible part was too small), `already-tagged`, `no-vehicle`. The `.md` gives per-category counts and shares, the identified rate, median top-1 similarity and margin for `team-obvious` and `weak-match`, then the worst boxes per category with their candidates, the failing rule and a suggested lever. It has no images, so it pastes into chat as is. `--report-top N` (default 20) caps the boxes listed per category; the `.json` always has every row, each with its `category`. To rebuild a report from a saved `boxes.json` without re-identifying: `python report.py BOXES_JSON OUT_PREFIX --report-top N`. Images that failed analysis are counted on a separate line, not in a category. Each `no-vehicle` image is listed with its burst and the detector's note (the strongest class and score it saw), which says whether a miss was a low score or a small box. Each box shows its detector score. The summary also lists the run's noise numbers, its possible new entries (`new_numbers`; each such box says `no entry has 115, read across the burst`) and its `entry list:` findings (the `.json` carries them as `noise_numbers` and `entry_list`), read from `boxes.json`, so a report rebuilt from a `boxes.json` written before them has neither. Three more sections follow the summary (they appear when `--report-top` is above 0, and the `.json` carries them as `detector_bands`, `sponsor_suggestions` and `bursts`): `## detector score` (boxes and identified count per score band, to judge the `DETECTOR_MIN_SCORE` cutoff), `## sponsor keyword suggestions` (words OCR read on identified boxes of one tag prefix that aren't in `rules.sponsor_keywords` yet, with how many unidentified boxes each would hint), and `## bursts` (capture-time gaps within and between the groups the plugin read, per group id). After the categories, `## resolved by pooled burst` lists the frames the experimental `burst_livery_pooling` rule named, weakest first, with the entry each took. `--archive-dir DIR` also copies `boxes.json` and the report into `DIR/<YYYYMMDD-HHMMSS>/` and keeps the newest 20 runs; the plugin passes `runs/` in its config directory, so earlier runs survive for comparison while `last-run/` stays the latest.

### Notes from the darktable source

- **`register_lib` takes eight positional arguments**: `(plugin_name, name, expandable, resetable, containers, widget, view_enter, view_leave)`. Leaving out `resetable` shifts the container table into a boolean slot and the panel never registers.
- **Registering a lib straight from `luarc` is a startup race.** darktable can report lighttable as the current view before the view has finished initialising, and a lib registered in that window is silently never attached (`src/views/view.c` documents it; the lua-scripts hit it as #19197). The plugin installs its panel from the `view-changed` event into lighttable instead, which fires only once the view is fully up.
- **`darktable-cli` never runs your `luarc`.** Since 5.6 the user `luarc` is loaded by `script_manager` (GUI only); before that the C code only loaded it when a GUI existed. `--luacmd` still runs, and it's the way to test headlessly. Anything GTK-wrapped (`register_lib`, `preferences.register`) blocks forever headless, so the plugin gates those on `dt.gui`.
- **Windows runs start with `start "" /B pythonw.exe launch.py <job>`.** The script and its arguments go in a job file, so none of them pass through cmd.exe. The command starts with `start`, not a quote, so cmd.exe keeps its quoted items intact (`lib/dtutils/system.lua` in darktable's lua-scripts wraps commands in a `.bat` because a command that starts with a quote gets mangled). There's no `.vbs`/`.bat` chain: antivirus behaviour checks (Bitdefender Advanced Threat Defense) flag a script host starting a hidden cmd from temp files. `pythonw.exe` must sit beside the `python.exe` the preference points at, as it does in a venv or a python.org install.
- **Native groups are read from `img.group_leader`.** Images sharing a leader are one group, and an image with no leader, or that is the only image sharing its leader, is its own group. A RAW+JPEG import pair is a native group (darktable groups them on import), so it counts as one group under **Native groups**. Assisted Grouping writes native groups only when its **Apply darktable groups** is on; with it off, **Native groups** sees just the import pairs and any groups you made by hand.
- **Combobox `changed_callback` runs asynchronously, and every `selected` assignment fires it** (`src/lua/widget/combobox.c`, `src/bauhaus/bauhaus.c`), even when refilling the list. So the collection list acts only when its value differs from the stored collection.
